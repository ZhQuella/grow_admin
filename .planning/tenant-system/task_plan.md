# 任务计划：租户系统分阶段实施

## 目标
在共享库表模式下建成完整 SaaS 租户系统：数据按 `tenant_id` 隔离，平台统一下发菜单/功能上限，租户内自主管理组织与权限，平台超级管理员可代操作进入租户。产品规则以 `docs/10-租户系统需求.md` 为准，实现方案以 `docs/11-租户系统技术.md` 为准。可读版实施计划见 `docs/12-租户系统实施计划.md`。

## 关键问题
1. 菜单/角色后端模块目前为空。阶段 5 是否允许先建最小菜单表，而不是等完整菜单管理 CRUD？**建议：允许。**
2. 组织人事表尚不存在。清空注册表第一期是否只覆盖账号/角色/授权/自建菜单？**建议：是，按实际存在的表注册。**
3. 会话作废需要 Redis 按租户索引 session。是否在阶段 3 一并做？**建议：是，否则停用/删除无法立即下线。**

## 已做决策
| 决策 | 理由 |
|------|------|
| 计划按「可演示切片」切分，前后端同一阶段交付 | 避免先堆完全部后端再开前端，每阶段都有可验收行为 |
| 组织人事完整实现不纳入本专项 | 那些页面前端已有、后端模块为空；本专项只要求它们落地时带租户隔离 |
| 无 Flyway，用增量 SQL 脚本 | 与当前 `scripts/sql/mysql/grow_admin.sql` 方式一致 |
| 阶段 5 可建最小菜单表 | 授权上限无法在没有菜单 ID 的情况下工作 |
| 租户管理菜单挂在「系统管理」下，不单开「平台管理」分组 | 2026-09-07 用户明确要求目录放在系统管理下面 |
