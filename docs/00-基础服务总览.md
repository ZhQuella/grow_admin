# 基础服务总览

## 1. 文档目标

本文档用于说明基础服务整体设计，作为各模块需求文档的入口。

基础服务覆盖：

- 部门管理
- 岗位管理
- 职位/职级管理
- 人员管理
- 账号管理
- 角色管理
- 菜单管理
- 组织架构图
- 导入导出

## 2. 核心设计原则

### 2.1 部门、岗位、人员解耦

部门、岗位、人员之间不直接写死关系，而是通过任职关系连接。

这样可以支持：

- 一人多部门
- 一人多岗位
- 主岗和兼岗
- 调岗历史
- 返聘记录
- 岗位编制
- 部门停用、迁移、合并后的历史追溯

### 2.2 岗位归属于部门

岗位由部门自行维护，不做全局岗位库。

例如：

- 研发部 / 前端工程师
- 研发部 / 后端工程师
- 财务部 / 会计

岗位数量通过编制表达。例如研发部需要 7 个前端工程师，应表达为：

- 岗位：前端工程师
- 所属部门：研发部
- 编制人数：7

不创建 7 条重复岗位记录。

### 2.3 职级全局独立维护

职位与职级在本系统表达同一概念，界面统一称为「职级」。职级是全局基础数据，用于表示人员任职层级。

例如：

- 专员
- 高级专员
- 主管
- 经理
- 总监

岗位与职级不绑定。人员任职时分别选择岗位和职级，因此同一岗位下的人员可以拥有不同职级。

### 2.4 权限以账号和角色为核心

权限链路：

```text
账号 -> 角色 -> 菜单权限 / 功能权限 / 数据权限
```

组织关系链路：

```text
账号 -> 绑定人员 -> 任职关系 -> 部门 / 岗位 / 上下级
```

角色不直接绑定部门、岗位或人员。

## 3. 核心关系模型

```text
部门
  └── 岗位

人员
  └── 任职关系
        ├── 部门
        ├── 岗位
        ├── 职级
        ├── 主职/兼职
        └── 历史记录

账号
  ├── 绑定人员
  └── 绑定角色

角色
  ├── 菜单权限
  ├── 功能权限
  ├── 行权限
  └── 列权限

菜单
  ├── 功能权限定义
  └── 表定义
        └── 字段定义
```

## 5. 全局业务规则

1. 部门支持多级结构。
2. 岗位归属于部门。
3. 职级全局维护，岗位与职级相互独立，人员任职时分别选择。
4. 岗位数量通过编制表达。
5. 人员必须通过任职关系绑定部门和岗位。
6. 人员必须且只能有一个主岗位。
7. 主岗位所属部门自动作为主部门。
8. 人员可多部门、多岗位、多上级。
9. 人员上下级关系单独维护。
10. 部门负责人最终必须指定到具体人员。
11. 部门停用、迁移、合并时需要处理人员去向。
12. 部门删除采用逻辑删除。
13. 岗位超编只提示，不阻止。
14. 兼职人员不占用编制。
15. 调岗、离职后自动释放编制。
16. 人员离职后账号自动停用。
17. 账号和人员一对一。
18. 未绑定人员账号允许登录。
19. 未绑定人员账号涉及组织类数据权限时默认全部数据。
20. 已绑定人员账号不可删除。
21. 非停用账号不可删除。
22. 角色绑定账号，不绑定人员、部门、岗位。
23. 角色停用后权限立即失效。
24. 多角色权限取并集。
25. 列权限冲突时可见优先。
26. 菜单、功能权限删除时，相关授权一并删除。
27. 字段标识修改时提示影响范围，确认后同步引用。
28. 导入重复编码时报错。
29. 导入人员时部门或岗位不存在则自动创建。
30. 导出受行权限和列权限控制。

## 6. 已确认实施边界

1. 本次改造只改前端：校验、二次确认、影响范围展示、交互和字段结构。权限计算与状态联动以后端为准。
2. 人员档案现有扩展字段保留（身份、合同、家庭、材料、员工类型等）。部门 / 岗位改为任职关系，不再在人员上单独维护主部门。
3. 行权限保留现有范围，并映射 / 扩展到组织条件。角色绑定账号、部门负责人、上下级与未绑人员账号的细则，以后续模块文档为准。
4. 岗位选择按下拉，接口先按 `/system/posts`（按部门过滤、仅启用岗位）。
5. 主职 = 主岗位，不拆成两个会打架的字段。
6. 人员不提供独立编辑页。新增走 `PersonCreate`，查看和改档案走 `PersonDetail` 分块编辑。账号信息、人事历史只读；人员状态不在档案编辑里改。任职的部门 / 岗位 / 任职类型变更走调岗抽屉，职级和上下级可在详情任职区块编辑。
7. 任职、紧急联系人、家庭信息至少保留一条，仅剩一条时删除按钮禁用。个人材料每项最多 1 个文件，已上传后隐藏上传按钮。
8. 调岗走 800px 右侧抽屉，不用类型下拉：点主职卡调整主职，点兼职卡调整兼职，置顶设为主岗，减号停止兼职，「+」新增兼职。设置为主岗只预览、点确定再提交，原地改类型，不二次确认。字段与任职卡片对齐。新增和详情分块编辑不填备注；生命周期备注选填。细则见 `03-人员管理.md` 第 8 节。

## 7. 当前代码实现概览（截至 2026-09-01）

当前 `DesignCornerstone/cornerstone-apps-system` 已注册并实现以下前端页面：

| 模块 | 页面组件 | 当前实现状态 |
|---|---|---|
| 菜单管理 | `MenuManage` | 已实现树形列表、新增编辑、启停、删除影响、功能配置和表字段配置 |
| 角色管理 | `RoleManage` | 已实现角色维护、账号绑定、菜单功能授权、行权限和字段可见/可编辑权限 |
| 账号管理 | `AccountManage` | 已实现账号维护、人员绑定/换绑/解绑、角色配置、权限明细、重置密码和历史 |
| 人员管理 | `PersonManage`、`PersonCreate`、`PersonDetail` | 已实现列表、新增、分块详情、任职调整及人员生命周期操作 |
| 部门管理 | `DeptManage` | 已实现部门树表、详情、新增编辑、迁移、合并、停用、启用和逻辑删除 |
| 岗位管理 | `PostManage` | 已实现按部门展开的岗位表、编制/人数统计、人员明细、详情和启停 |
| 职级管理 | `PositionManage` | 已实现独立职级列表、新增编辑、启停、引用影响和删除 |
| 组织架构图 | `OrgChart` | 已实现部门树、ECharts 关系图、三种展示模式、筛选定位和节点详情 |

实现边界：

- 页面通过 `src/api/system*.ts` 维护接口契约，通过 `src/types/system*.ts` 维护前端领域类型。
- 当前仓库同时提供 `sample/mock/system*.ts` 作为演示数据和交互验证，不代表正式后台已经完成。
- 通用导入导出尚未在 `cornerstone-apps-system` 注册页面。
- 岗位与职级在代码中独立维护；人员任职分别保存部门、岗位和职级，不做自动联动。
