# 部门管理

## 1. 功能定位

部门管理用于维护组织结构，支持多级部门、部门负责人、部门停用、部门迁移、部门合并、部门撤销/删除。

部门是组织结构单元，不直接保存人员归属关系。人员通过任职关系归属于部门。

## 2. 页面布局

部门管理采用与菜单管理一致的「树形表格」布局。

```text
顶部：新增部门 + 刷新 + 搜索筛选 + 列配置
主体：可展开/收起的部门树形表格
行内操作：新增子部门 / 查看 / 编辑 / 迁移 / 合并 / 停用 / 启用 / 删除
抽屉：部门详情 / 新增编辑 / 部门岗位 / 部门人员 / 子部门
```

### 2.1 部门树形表格

展示内容：

- 部门名称
- 部门编码
- 上级部门
- 部门负责人
- 直属岗位数量
- 有效人员数量
- 直属子部门数量
- 排序号
- 部门状态
- 更新时间（默认隐藏，可通过列配置展示）
- 行内操作

交互：

- 部门按层级直接显示在表格中，支持展开和收起。
- 点击部门名称或查看操作，通过抽屉展示部门详情。
- 支持按部门名称、部门编码搜索，并按状态筛选；匹配子部门时保留其上级路径。
- 支持列显示配置。
- 点击直属岗位、有效人员、子部门数量，通过抽屉展示对应列表。
- 停用部门整行使用弱化样式展示。
- 已删除部门不在有效部门树形表格中展示。
- 隐藏虚拟根节点「全部」，直接展示顶级部门。

### 2.2 部门详情抽屉

展示：

- 顶部身份区：部门名称、部门编码、上级部门、状态
- 组织规模：有效人员、直属岗位、直属子部门
- 部门负责人及负责人来源
- 基础信息：部门名称、部门编码、上级部门、排序号、描述、创建时间、更新时间
- 负责人历史

详情不使用独立页签。使用宽抽屉并优先按多列铺开信息，减少纵向堆叠。「有效人员」「直属岗位」「直属子部门」在详情内直接以三列列表平铺展示，不需要再次点击进入；窄屏时自动回落为两列或单列。表格中的对应数量仍可作为快捷入口，通过抽屉单独查看列表。

## 3. 字段说明

| 字段 | 是否必填 | 控件 | 说明 |
|---|---:|---|---|
| 部门名称 | 是 | 输入框 | 部门展示名称 |
| 部门编码 | 是 | 输入框 | 部门唯一编码 |
| 上级部门 | 否 | 树选择 | 顶级部门可为空 |
| 部门负责人类型 | 否 | 单选 | 人员 / 岗位 |
| 部门负责人 | 否 | 人员选择 | 最终负责人必须是具体人员 |
| 排序号 | 否 | 数字输入 | 部门展示排序 |
| 状态 | 是 | 单选/标签 | 启用 / 停用 |
| 部门描述 | 否 | 多行文本 | 说明 |

部门名称允许重复，部门编码全局唯一。排序号默认 `0`，仅在同级部门之间生效；同级部门按排序号升序排列，排序号相同时按创建时间排列。

## 4. 页面操作

顶部按钮：

- 新增部门
- 刷新
- 搜索筛选
- 列配置

行内按钮：

- 新增子部门
- 查看详情
- 编辑部门
- 启用
- 停用
- 迁移
- 合并
- 删除

显示规则：

- 顶部始终显示新增部门和刷新。
- 启用部门行显示新增子部门、查看、编辑、停用、迁移、合并。
- 停用部门行显示查看、启用、删除。
- 删除仅对停用部门显示。

## 5. 新增部门

入口：点击「新增部门」。

打开方式：右侧抽屉。

字段：

- 部门名称
- 部门编码
- 上级部门
- 排序号
- 部门描述

新增时不设置部门负责人，创建后通过编辑部门维护负责人。

校验：

- 部门名称不能为空。
- 部门编码不能为空。
- 部门编码必须唯一。
- 上级部门只能选择启用部门。
- 不选择上级部门时，创建为顶级部门。

保存后：

- 新部门默认启用。
- 部门树形表格刷新。

## 6. 编辑部门

入口：选中部门后点击「编辑部门」。

打开方式：右侧抽屉。

可编辑：

- 部门名称
- 部门编码
- 上级部门
- 部门负责人
- 排序号
- 部门描述

特殊规则：

- 部门编码允许修改，修改后仍需通过唯一性校验。
- 不允许将上级部门设置为自己。
- 不允许将上级部门设置为自己的下级部门。
- 修改上级部门属于部门迁移，应提示用户。

提示文案：

```text
修改上级部门将触发部门迁移规则，是否继续？
```

## 7. 部门负责人

部门负责人支持两种方式：

- 选择人员
- 选择岗位作为候选范围，再从该岗位下选择一名人员作为主负责人

### 7.1 选择人员

交互：

1. 负责人类型选择「人员」。
2. 人员选择器仅展示当前部门存在有效主职或兼职任职的正式人员。
3. 保存后负责人显示为人员姓名。

校验：

- 所选人员必须在当前部门存在有效主职或兼职任职。
- 仅正式人员可作为负责人。

### 7.2 选择岗位

交互：

1. 负责人类型选择「岗位」。
2. 先选择当前部门下的岗位。
3. 再从该岗位下选择一名存在有效主职或兼职任职的正式人员作为主负责人。
4. 保存后展示岗位名称和主负责人姓名。

校验：

- 岗位必须属于当前部门。
- 岗位下没有可选人员时，提示不可保存。

提示文案：

```text
该岗位暂无可选人员，请先为该岗位分配人员。
```

## 8. 部门停用

部门停用表示部门暂不可用，但可恢复。

入口：选中启用部门，点击「停用」。

打开方式：右侧宽抽屉，使用两步向导。影响范围和人员处理信息使用可用宽度横向铺开，窄屏时再回落为单列。

### 8.1 第一步：影响范围检查

展示：

- 当前部门名称
- 子部门数量
- 启用岗位数量
- 在职人员数量
- 部门负责人

停用范围为当前部门及其全部下级部门。下级部门随当前部门一起停用。

如果停用范围内存在有效任职，进入人员去向分配。

如果停用范围内不存在有效任职，第一步直接显示「确认停用」，不展示空的人员去向步骤。

### 8.2 第二步：人员去向分配

页面结构：

```text
顶部：统一设置区域
  - 目标部门
  - 目标岗位
  - 应用到全部

下方：人员列表
  - 姓名
  - 工号
  - 任职类型
  - 当前部门
  - 当前岗位
  - 目标部门
  - 目标岗位
  - 调整原因
```

交互：

- 人员去向按有效任职关系逐条处理。同一人员存在多条有效任职时，分别展示和处理。
- 处理范围包括当前部门及全部下级部门中的所有有效主职和兼职任职。
- 用户可统一设置目标部门和目标岗位。
- 点击「应用到全部」后，所有人员填充目标部门和目标岗位。
- 用户可对单个人员单独修改目标部门和目标岗位。
- 每条任职独立展示当前部门、当前岗位、处理方式、目标部门、目标岗位、调整原因和完成状态。
- 顶部展示已完成任职数 / 待处理任职总数。
- 主职必须迁往停用范围外的启用部门和启用岗位。
- 兼职可选择迁往停用范围外的启用部门和启用岗位，也可选择直接结束兼职。
- 所有主职均设置去向、所有兼职均设置迁移去向或结束方式后，才允许确认停用。

确认后：

- 系统批量生成调岗记录。
- 当前部门及全部下级部门状态变为停用。
- 停用范围内的岗位同步停用。
- 部门不可再新增人员和岗位。
- 停用范围内的部门负责人自动清空，并保留负责人变更历史。
- 人员管理中的主职、兼职及历史任职需要对停用部门或停用岗位展示特殊状态标识。

## 9. 部门启用

入口：选中停用部门，点击「启用」。

校验：

- 上级部门必须为启用状态。

启用后：

- 部门恢复为启用状态。
- 启用流程展示停用部门树，由用户勾选本次需要恢复启用的部门；未勾选部门继续保持停用。
- 勾选子部门时自动勾选其上级，取消上级时自动取消其下级。
- 对本次勾选启用的部门，仅恢复该次级联停用前原本启用的岗位；原本已停用的岗位不恢复。
- 可重新新增岗位和分配人员。
- 历史记录不变。

## 10. 部门迁移

部门迁移指调整部门的上级部门。

入口：点击「迁移」。

打开方式：右侧宽抽屉。当前位置、迁移后位置和调整范围优先横向铺开。

抽屉顶部使用「当前位置 → 迁移后位置」对照展示；选择目标上级后实时更新迁移后位置。

字段：

- 目标上级部门

规则：

- 目标上级部门不可为自己。
- 目标上级部门不可为自己的下级部门。
- 部门迁移仅调整上级部门。
- 人员任职和岗位仍归属于原部门，随部门结构自然迁移，不提供额外的人员或岗位跟随开关。
- 确认区明确展示本次迁移的组织节点范围，并说明人员任职、岗位和负责人均不发生归属变更。
- 目标上级与当前上级相同时，确认按钮不可用。

完成后：

- 部门树刷新。
- 原任职历史保留。

## 11. 部门合并

部门合并指将一个部门合并到另一个目标部门。

入口：点击「合并」。

目标部门必须为启用部门，不可为源部门自身或源部门的任意下级部门。

使用右侧宽抽屉步骤向导，步骤内容使用可用宽度横向铺开，不设置内部窄版心：

1. 选择接收部门，展示「源部门 → 接收部门」对照及本次影响数量。
2. 设置岗位映射，每个源岗位独立展示处理方式、目标岗位及完成状态。
3. 设置组织处理方式，包括需要迁移的直属子部门、源负责人处理方式、是否停用源部门。
4. 仅在停用源部门且存在剩余有效任职时，展示人员去向步骤并逐条处理。
5. 展示最终确认摘要，汇总源部门、接收部门、岗位映射、子部门迁移、负责人处理、源部门状态和额外人员处置数量。

没有剩余有效任职时，跳过人员去向步骤，直接进入最终确认。

### 11.1 岗位映射

表格：

| 原岗位 | 原岗位人数 | 目标岗位 | 处理方式 |
|---|---:|---|---|
| 前端工程师 | 7 | 目标部门前端工程师 | 映射 |
| 后端工程师 | 12 | 新建目标岗位 | 新建 |

规则：

- 同名岗位不自动合并。
- 必须人工选择映射关系。
- 未完成岗位映射，不允许下一步。
- 支持「新建目标岗位」。表单与岗位管理的新增岗位完全对齐，包括岗位名称、岗位编码、岗位类型、三类编制、岗位职责、任职要求、排序号和岗位说明；默认带入源岗位配置，保存前可修改。

合并后：

- 人员根据岗位映射转入目标部门对应岗位。
- 由用户选择是否停用原部门。
- 原部门直属岗位和人员根据岗位映射迁入目标部门。
- 用户勾选的子部门只调整上级部门，其人员和岗位保持不变。
- 用户不勾选停用原部门时，未勾选迁移的子部门留在原部门下并保持原状态。
- 用户勾选停用原部门时，未勾选迁移的子部门随原部门一起停用；其有效任职逐条分配去向，岗位同步停用。
- 原部门历史记录保留。
- 目标部门原负责人默认不变。
- 用户可选择使用源部门负责人替换目标部门负责人，或取消源部门负责人。选择替换时，该人员迁移后必须是目标部门存在有效主职或兼职任职的正式人员。
- 合并完成后源部门负责人自动清空，并保留负责人变更历史。

## 12. 部门撤销/删除

部门撤销等同删除，但采用逻辑删除。

规则：

- 仅停用部门可删除。
- 删除时由用户选择是否同时逻辑删除全部下级部门。
- 未选择同时删除时，只要当前部门存在下级部门，就禁止提交删除。
- 选择同时删除时，逻辑删除当前部门及其整棵下级部门树。
- 删除前展示删除范围内存在有效主职或兼职任职的相关人员列表。
- 用户选择是否一并取消相关人员的部门任职关联。
- 选择取消关联时，对删除范围内的相关有效任职执行结束处理，主职不要求重新选择部门或岗位，也不阻塞删除；主职和兼职均转为已结束任职，结束原因记录为「部门删除」，历史保留。
- 不取消关联时保留有效任职，但对应部门或岗位在人员管理中显示「部门已删除」并置灰；此类任职不再参与当前组织结构和数据权限计算。
- 删除后部门不再可选。
- 删除后不作为有效组织展示。
- 历史记录仍保留原部门名称和引用关系。
- 部门下的停用岗位继续作为历史数据保留，并随部门从有效选项中隐藏。
- 角色数据权限中已引用该部门的配置继续保留并标记部门失效，不自动转移到其他部门。
- 停用或删除状态标识仅展示在当前有效任职上；已经结束的历史任职保持原部门和岗位名称，不追加新的状态标识。

确认弹窗展示：

- 部门名称
- 历史任职记录数量
- 当前有效任职人员列表
- 是否取消相关人员部门任职关联
- 是否同时删除全部下级部门
- 历史引用说明
- 删除后不可作为有效部门使用

提示文案：

```text
该操作将删除部门的有效状态，但历史记录仍会保留。请确认是否删除。
```

## 13. 本期实施边界

- 本期暂不实现部门导入、导出，页面不提供对应操作入口。

## 14. 组件与交互约定

- 新增、编辑共用一个右侧抽屉，通过 `component :is` 切换内容组件。
- 停用、合并使用全屏步骤抽屉。
- 迁移使用 Dialog。
- 启用、删除使用确认 Dialog；需要选择部门或展示影响范围时，在 Dialog 内完成。
- 部门岗位、部门人员、子部门使用抽屉展示，不设置独立页签。
- 基础信息中展示可见的负责人变更历史。
