## 2. 总体架构

### 2.1 租户隔离模式

共享库表：除平台级全局表外，租户业务表全部增加 `tenant_id`。查询、更新、删除、统计都必须带 `tenant_id`。

### 2.2 租户上下文

后端请求上下文统一解析：

- `tenantId` / `tenantCode`
- `accountId` / `username`
- `platformAdmin`
- `actingTenantId` / `actingTenantCode`
- `impersonating`

普通租户账号：

```text
tenantId = 账号所属租户
actingTenantId = null
impersonating = false
```

平台超级管理员访问平台（`tenantCode = platform`）：

```text
tenantId = platform
platformAdmin = true
actingTenantId = null
impersonating = false
```

平台超级管理员代操作：

```text
tenantId = platform
platformAdmin = true
actingTenantId = 目标租户ID
actingTenantCode = 目标租户编码
impersonating = true
```

业务数据租户 ID：

```text
effectiveTenantId = impersonating ? actingTenantId : tenantId
```

代操作时前端不渲染「平台管理」，后端 `/platform/**` 在 `impersonating = true` 时一律拒绝。

### 2.3 权限边界

- 平台超级管理员：可访问平台管理；代操作时拥有目标租户授权上限内全部能力，不可访问平台管理。
- 租户管理员：只访问本租户；`TENANT_ADMIN` 权限 = 当前租户授权全集，由后端同步，不在角色管理中编辑。
- 普通账号：只访问本租户；权限来自普通角色，且必须是上限子集。

## 3. 数据库设计

### 3.1 命名约定

- 主键 `BIGINT UNSIGNED`。
- 租户字段统一 `tenant_id`。
- 逻辑删除统一 `deleted_at`。
- 时间字段 `DATETIME(3)`。
- 租户生命周期状态使用 `VARCHAR(32)`。
- 日期比较与到期任务统一按 `Asia/Shanghai`。

### 3.2 租户表：sys_tenant

在现有表上升级，补齐字段。不再使用 0/1 状态。不保留 `contact_phone`。

```sql
CREATE TABLE IF NOT EXISTS `sys_tenant` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '租户ID',
    `tenant_code` VARCHAR(64) NOT NULL COMMENT '租户编码，登录组织代码',
    `tenant_name` VARCHAR(128) NOT NULL COMMENT '租户名称',
    `short_name` VARCHAR(64) NULL COMMENT '租户简称',
    `tenant_type` VARCHAR(32) NOT NULL DEFAULT 'company' COMMENT 'company/school/government/organization/other',
    `status` VARCHAR(32) NOT NULL DEFAULT 'not_opened' COMMENT 'not_opened/trial/active/expired/disabled/deleted',
    `started_at` DATETIME(3) NULL COMMENT '服务开始时间，开通当天 00:00:00',
    `expired_at` DATETIME(3) NULL COMMENT '服务到期时间，结束日 23:59:59',
    `contact_name` VARCHAR(64) NULL COMMENT '联系人姓名',
    `contact_mobile` VARCHAR(32) NULL COMMENT '联系人手机号',
    `contact_email` VARCHAR(128) NULL COMMENT '联系人邮箱',
    `credit_code` VARCHAR(64) NULL COMMENT '统一社会信用代码',
    `industry` VARCHAR(64) NULL COMMENT '行业，自由输入',
    `region_code` VARCHAR(32) NULL COMMENT '地区编码',
    `address` VARCHAR(255) NULL COMMENT '地址',
    `remark` VARCHAR(500) NULL COMMENT '备注',
    `built_in` TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '是否内置',
    `last_login_at` DATETIME(3) NULL COMMENT '最近一次非代操作登录时间',
    `created_by` BIGINT UNSIGNED NULL COMMENT '创建人账号ID',
    `updated_by` BIGINT UNSIGNED NULL COMMENT '更新人账号ID',
    `created_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    `updated_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    `deleted_at` DATETIME(3) NULL COMMENT '删除时间',
    PRIMARY KEY (`id`),
    KEY `idx_sys_tenant_code` (`tenant_code`),
    KEY `idx_sys_tenant_status` (`status`),
    KEY `idx_sys_tenant_expired_at` (`expired_at`),
    CONSTRAINT `ck_sys_tenant_status` CHECK (`status` IN ('not_opened', 'trial', 'active', 'expired', 'disabled', 'deleted')),
    CONSTRAINT `ck_sys_tenant_built_in` CHECK (`built_in` IN (0, 1))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='租户';
```

编码唯一性不靠全表 UNIQUE 实现，因为已到期/已停用/已删除允许复用。后端在试用/开通时校验：不存在其他 `status IN ('trial','active')` 且 `tenant_code` 相同的记录。列表展示与登录按当前记录的 `tenant_code` + `status` 解析。

建议部分唯一索引（MySQL 8.0.13+ 函数索引或生成列）：

```sql
ALTER TABLE `sys_tenant`
    ADD COLUMN `active_code` VARCHAR(64)
        GENERATED ALWAYS AS (
            CASE WHEN `status` IN ('trial', 'active') THEN `tenant_code` ELSE NULL END
        ) VIRTUAL,
    ADD UNIQUE KEY `uk_sys_tenant_active_code` (`active_code`);
```

## 4. 后端接口清单

接口返回继续沿用现有 `Result<T>`。`/platform/**` 仅平台超级管理员且 `impersonating = false`。

### 4.1 租户管理

#### 分页查询

```text
POST /platform/tenants/page
```

筛选：`keyword`、`status`（含 `not_opened`）、`createdStartAt`、`createdEndAt`、`expiredStartAt`、`expiredEndAt`、`page`、`pageSize`。

列表项在原 `TenantListItem` 上去掉 `contactPhone`，状态枚举改为本节定义。`lastLoginAt` 不含代操作。

#### 详情 / 创建 / 更新

```text
POST /platform/tenant/detail
POST /platform/tenant/create
PUT  /platform/tenant
```

创建、更新请求**不含** `startedAt`、`expiredAt`、`status`、`tenantCode`（更新时编码走独立接口）。创建成功后状态为 `not_opened`，并插入 `TENANT_ADMIN`。

#### 修改编码

```text
PUT /platform/tenant/code
```

字段：`tenantId`、`newTenantCode`、`confirmTenantCode`、`reason`。`platform` 拒绝。已发出 token 不强制下线。

#### 试用

```text
POST /platform/tenant/trial
```

| 字段 | 必填 | 说明 |
|---|---:|---|
| tenantId | 是 | |
| expiredOn | 是 | 结束日期 `yyyy-MM-dd`，服务端写成当天 23:59:59 |
| reason | 是 | 审计 |

允许当前状态：`not_opened`、`expired`、`disabled`。`platform` 拒绝。

服务端写入：

```text
started_at = 当天 00:00:00 Asia/Shanghai
expired_at = expiredOn 23:59:59 Asia/Shanghai
status = trial
```

`expiredOn` 不得早于当天。

#### 开通

```text
POST /platform/tenant/activate
```

字段同试用。允许当前状态：`not_opened`、`trial`、`expired`、`disabled`。结果 `status = active`。日期规则相同。

#### 停用

```text
POST /platform/tenant/disable
```

字段：`tenantId`、`reason`。允许：`trial`、`active`。结果 `disabled`，立即作废该租户全部 refresh token / 会话。

不提供通用 `PUT /platform/tenant/status`，页面不能把状态改成 `deleted`。

#### 删除

```text
POST /platform/tenant/delete
```

字段：`tenantId`、`confirmTenantCode`、`reason`。结果 `deleted` + `deleted_at`，立即作废会话。不可从已删除恢复。

#### 清空影响 / 清空数据

```text
POST /platform/tenant/clear-impact
POST /platform/tenant/clear-data
```

清空保留：`sys_tenant`、授权两张表、`TENANT_ADMIN` 角色行、编码变更日志、代操作审计。其余带目标 `tenant_id` 的业务表删除。清空后按授权重建 `TENANT_ADMIN` 权限。

### 4.2 租户授权

```text
POST /platform/tenant/grant/detail
PUT  /platform/tenant/grant
```

保存为覆盖写。随后：

1. 同步 `TENANT_ADMIN` 角色权限 = 本次授权全集。
2. 清理普通角色中超出上限的菜单/功能授权。
3. 不踢用户下线；下次请求鉴权即失效。

授权树不含「平台管理」节点。给 `platform` 租户的新平台菜单在菜单保存时自动写入授权表，不走此 UI。

### 4.3 平台侧租户账号

```text
POST /platform/tenant-accounts/page
POST /platform/tenant-account/create
PUT  /platform/tenant-account
POST /platform/tenant-account/assign-tenant-admin
```

创建时必须带 `tenantId`。分配 `TENANT_ADMIN` 仅此入口。不可在此给非 `platform` 账号打 `is_platform_admin`。

系统管理账号接口仍按 `effectiveTenantId` 过滤，不接受前端传入的 `tenantId`。

### 4.4 登录与代操作

继续：

```text
POST /account/login
```

字段：`tenantCode`、`username`、`password`、`captchaId`、`captchaCode`。

普通登录：

1. 校验验证码。
2. 按 `tenantCode` 查找租户（优先 `trial/active`；编码复用场景下只命中当前可登录租户）。
3. 状态必须是 `trial` 或 `active`，且当前时间 ≤ `expired_at`。否则按实际状态提示：未开通 / 已到期 / 已停用 / 已删除。
4. 即使任务尚未把状态写成 `expired`，只要 `now > expired_at` 也按已到期拒绝，并回写状态。
5. 按 `tenant_id + username` 查启用账号，校验密码。
6. 查角色权限（`TENANT_ADMIN` 取授权全集）。
7. 生成 JWT。
8. 非代操作时更新账号 `last_login_at` 和租户 `last_login_at`。

代操作登录：

1. 目标租户必须是 `trial` 或 `active`（同样校验未过 `expired_at`）。
2. 目标租户没有该用户名时，再在 `platform` 查找 `is_platform_admin = 1` 的账号并校验密码。
3. 目标租户已有同名账号则走普通登录，不代操作。
4. JWT：`impersonating = true`，`effectiveTenantId` = 目标租户。
5. 不更新目标租户 `last_login_at`。
6. 代操作权限 = 目标租户授权上限全集 + 该租户自建菜单能力，不查平台管理权限。

JWT claims 增加：`effectiveTenantId`、`effectiveTenantCode`、`impersonating`、`operatorAccountId`、`operatorUsername`。

会话作废：停用、到期、删除时删除该 `effectiveTenantId` 下全部 refresh token。改编码不删。

### 4.5 代操作审计

```text
POST /platform/tenant/impersonation-audits/page
POST /platform/tenant/impersonation-audit/detail
```

`impersonating = true` 的请求由 WebFilter 写入 `sys_tenant_impersonation_audit`，成功失败都记。GET 是否记录：记（需求为代操作接口调用均生成日志）。参数脱敏。

## 6. 到期任务

不再使用凌晨 3 点任务。

规则：`expired_at` 存结束日 23:59:59 `Asia/Shanghai`。当前时间大于该点：

- 登录与鉴权立即按已到期拒绝。
- 定时任务把 `trial/active` 且 `expired_at < now` 的记录更新为 `expired`，并作废会话。

任务建议每分钟扫描，或每小时扫描 + 登录时补偿回写，保证列表状态最终一致。`platform` 排除。`not_opened` 且无日期的记录不改为 `expired`。

## 7. 租户过滤

Mapper 层租户业务表必须带 `effectiveTenantId`。禁止前端传入的 `tenantId` 决定业务数据范围，除非 `/platform/**`。

平台接口例外：`/platform/**` 可显式传目标 `tenantId` 管理租户。

## 8. 授权与角色联动

保存普通角色菜单/功能时：

```text
role.menuIds ⊆ tenant.menuIds ∪ tenantSelfMenuIds
role.functionIds ⊆ tenant.functionIds ∪ tenantSelfFunctionIds
```

保存 `TENANT_ADMIN` 权限的接口直接拒绝，改授权时由服务端覆盖写入。

数据权限依附的菜单必须属于已授权平台菜单或本租户自建菜单。

## 9. 清空租户数据

后端编排，维护清空注册表。本期对业务表物理删除。顺序建议：运行时 → 设计器 → 普通角色与授权 → 组织人事 → 账号 → 业务数据。跳过并保留：

- `sys_tenant`
- `sys_tenant_menu` / `sys_tenant_menu_function`
- `sys_tenant_menu_alias`（可选保留；自建菜单已删，平台菜单别名可清可留，本期保留）
- `TENANT_ADMIN` 角色行
- 编码变更日志、代操作审计

然后按授权重建 `TENANT_ADMIN` 的角色菜单/功能。失败返回失败表名。

## 10. 迁移

1. 升级 `sys_tenant` 结构，插入或更新 `platform`：`built_in = 1`，`status = active`，`started_at/expired_at` 可空（内置不参与到期）。
2. 历史数据 `tenant_id` 回填 `platform`。
3. 为 `platform` 插入 `TENANT_ADMIN`，并把现有平台菜单全部写入 `sys_tenant_menu`（自动授权）。
4. 唯一索引改为 `tenant_id + code`。
5. 现有 `platform/admin` 保持 `is_platform_admin = 1`。

2. 平台管理路由与代操作横幅。
3. 租户列表、详情、编辑、编码、试用/开通/停用/删除/清空/授权。
4. 租户账号页。
5. 代操作审计页。
6. 系统管理账号（超管标记）、角色（内置保护与授权过滤）、菜单（别名 + 自建自动化/外链）。

## 12. 测试要点

登录与隔离、授权上限、菜单别名与自建 CRUD、代操作与审计、清空保留授权、`platform` 保护、编码复用（仅非试用中/已开通可复用）、到期 23:59:59、停用/删除立即下线、改编码 token 仍可用至过期。细则与需求文档第 7 节验收标准对齐。

## 13. 风险

1. 漏加 `tenant_id` 导致串租户。
2. 编码复用后旧租户无法再开通，需在试用/开通时明确提示撞码。
3. 授权上限必须后端强校验。
4. 代操作 JWT 与审计必须可区分真实租户用户。
5. 清空是高危操作，须影响范围、确认编码、原因、审计、保护 `platform`。
6. 到期以 `expired_at` 为准，不能只靠列表上的状态字段。
