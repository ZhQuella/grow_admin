## 1. 背景与目标

当前系统已经具备部门、岗位、职级、人员、账号、角色、菜单、功能权限、数据权限等基础管理能力。后端已有最小租户雏形：

- `sys_tenant`：租户表。
- `sys_account.tenant_id`：账号归属租户。
- 登录请求已包含 `tenantCode`。
- JWT 已写入 `tenantId`、`tenantCode`、`platformAdmin`。

本次目标是在现有基础上建设完整 SaaS 租户系统：多租户共享库表、数据按 `tenant_id` 强隔离、平台统一下发菜单与功能权限上限、租户内自主管理组织/账号/角色/权限，并支持平台超级管理员以代操作方式进入租户环境。

说明：现有前端基础服务文档中曾约定「只改前端」，该约定不作为本次租户系统建设边界。本次需求覆盖前端、后端、数据库、接口、权限与迁移。

后台分组约定：

- **系统管理**：租户使用，数据范围始终为当前租户。
- **平台管理**：仅平台超级管理员使用，用于跨租户治理。

## 2. 核心结论

| 项目 | 结论 |
|---|---|
| 租户定义 | SaaS 客户/公司 |
| 隔离模式 | 共享库表，租户业务数据统一加 `tenant_id` |
| 登录方式 | 沿用 `tenantCode + username + password + captcha` |
| 管理入口 | 新增「平台管理」：租户管理、租户账号、代操作审计 |
| 平台管理后台 | 不单独建设，放在当前后台统一管理 |
| 租户初始化 | 创建租户自动插入内置角色 `TENANT_ADMIN`；不自动创建账号、部门、菜单 |
| 租户管理员 | 仅平台超级管理员可分配；数量不限；权限自动等于该租户授权上限全集 |
| 菜单策略 | 平台统一下发菜单和功能权限上限；新菜单只自动授予 `platform`，其他租户须再授权 |
| 平台下发菜单 | 租户只能改本租户显示名称；不可改路径/组件、不可删、不可停用 |
| 租户自建菜单 | 仅可自建自动化菜单和外部页面；可改、可删、可选挂载位置；须已授权对应功能权限 |
| 租户生命周期 | 未开通、试用中、已开通、已到期、已停用、已删除 |
| 状态如何变 | 页面不提供「改状态」；只通过试用、开通、停用、删除和到期自动变更 |
| 可登录状态 | 仅试用中、已开通 |
| 删除方式 | 逻辑删除；清空数据通过独立操作执行 |
| 套餐限制 | 暂不做账号数、人员数、存储、页面数等套餐限制 |
| 品牌自定义 | 暂不支持 |
| 账号归属 | 账号只属于一个租户；`tenantCode + username` 唯一 |
| 代操作 | 平台超级管理员用目标租户组织代码登录；不从租户列表进入；代操作时不可用平台管理；退出即退出登录 |
| 默认租户 | `platform` 作为平台内置租户，历史数据迁入该租户 |

## 3. 用户角色

### 3.1 平台超级管理员

识别方式：`platform` 租户下账号的 `is_platform_admin` 标记。仅 `platform` 租户账号可被标记；数量不限。标记入口在 **系统管理 / 账号管理**（须以 `platform` 身份登录）。

能力：

- 查看所有租户。
- 创建、编辑租户信息。
- 对租户执行试用、开通、停用、删除。
- 修改租户编码（二次确认）。
- 逻辑删除租户。
- 清空租户数据。
- 在租户列表为租户配置菜单与功能权限上限。
- 在「平台管理 / 租户账号」按租户创建账号，并分配内置「租户管理员」角色。
- 使用目标租户组织代码登录进行代操作。
- 查看代操作审计日志。

限制：

- `platform` 内置租户只能编辑信息，不可试用、开通、停用、删除、改编码、清空、授权（新平台菜单自动授予 `platform`）。
- 代操作时不可访问「平台管理」，退出代操作必须退出登录。
- 目标租户不是试用中或已开通时，不能代操作进入。

### 3.2 租户管理员

每个租户固定存在内置角色「租户管理员」（`TENANT_ADMIN`）。创建租户时自动插入该角色。角色名称、编码由平台统一设定，租户不可改。

能力：

- 维护本租户部门、岗位、职级、人员、账号。
- 新建、编辑、停用、删除本租户普通角色。
- 给本租户账号绑定普通角色。
- 在平台授权上限内为普通角色配置菜单、功能、数据、字段权限。
- 在已授权的菜单管理功能权限内，新增、修改、删除本租户自建自动化菜单和外部页面。

限制：

- 不可见、不可改平台超级管理员账号（账号按租户隔离，租户列表中不会出现平台超管）。
- 不可突破平台下发的菜单和功能权限上限。
- 不可修改内置「租户管理员」角色的权限、编码、名称，不可删除、停用该角色。
- 不可给账号分配 `TENANT_ADMIN`（仅平台超级管理员可分配）。
- 不可访问平台管理。
- 不可把平台下发菜单改路径、删除或停用；仅可改本租户显示名称。

### 3.3 租户普通账号

权限由本租户所绑角色决定，且角色权限必须是租户授权上限的子集。

限制：

- 不能跨租户访问数据。
- 不能切换租户。
- 不能访问平台管理。

## 4. 业务范围

### 4.1 本次包含

- 平台管理分组：租户管理、租户账号、代操作审计。
- 租户基础信息与生命周期（试用、开通、停用、删除、到期）。
- 租户菜单与功能权限上限配置。
- 租户编码修改二次确认。
- 租户逻辑删除与数据清空。
- 登录按 `tenantCode` 识别租户；JWT 与后端上下文携带租户身份。
- 各业务表增加 `tenant_id` 隔离。
- 平台超级管理员代操作与代操作审计。
- 历史数据迁移到 `platform`。
- 系统管理中账号、角色、菜单按租户规则改造。

### 4.2 本次不包含

- 独立平台管理后台。
- 租户套餐、计费、资源额度限制。
- 租户品牌自定义。
- 一个账号加入多个租户。
- 每租户独立数据库或独立 Schema。
- 普通操作全量审计闭环，只预留表结构或字段。
- 已开通期间提前续期（到期后再开通）。
- 已删除租户恢复。

## 5. 功能需求

## 5.1 平台管理分组

新增一级分组「平台管理」。

菜单：

- 租户管理。
- 租户账号。
- 代操作审计。

可见规则：

- 仅平台超级管理员可见。
- 非平台超级管理员不可见，不可通过路由直接访问。
- 代操作状态下隐藏且不可访问。

## 5.2 租户管理

### 页面布局

租户管理采用列表页。

筛选区字段：

| 字段 | 控件 | 说明 |
|---|---|---|
| 关键词 | 输入框 | 支持租户编码、租户名称、简称、联系人搜索 |
| 租户状态 | 下拉选择 | 全部、未开通、试用中、已开通、已到期、已停用、已删除 |
| 创建时间 | 日期范围 | 按创建时间筛选 |
| 到期时间 | 日期范围 | 按服务到期时间筛选 |

列表列：

| 字段 | 说明 |
|---|---|
| 租户编码 | 登录组织代码 |
| 租户名称 | SaaS 客户/公司名称 |
| 租户简称 | 列表展示用 |
| 状态 | 生命周期状态 |
| 联系人 | 客户侧联系人 |
| 联系人手机 | 仅保留这一列联系方式 |
| 账号数 | 当前租户账号数量 |
| 人员数 | 当前租户人员数量 |
| 服务期限 | 开始日期至结束日期；未开通时为空 |
| 最后登录时间 | 租户下账号最近一次**非代操作**登录时间 |
| 创建时间 | 租户创建时间 |
| 操作 | 按当前状态展示可用操作 |

列表不提供「进入租户」「改状态」。

操作总览：

- 新增租户。
- 查看、编辑。
- 授权。
- 试用、开通、停用。
- 修改租户编码。
- 清空租户数据。
- 删除租户。

`platform` 行：只提供查看与编辑信息。

### 租户字段

| 字段 | 字段名 | 必填 | 控件 | 规则 |
|---|---|---:|---|---|
| 租户ID | tenantId | 系统生成 | 文本 | 后端生成，前端展示 |
| 租户编码 | tenantCode | 是 | 输入框 | 2-64 位，字母、数字、下划线、短横线；登录组织代码 |

| 租户简称 | shortName | 否 | 输入框 | 最多 64 位 |
| 租户类型 | tenantType | 否 | 下拉选择 | company、school、government、organization、other |
| 状态 | status | 系统维护 | 标签 | not_opened、trial、active、expired、disabled、deleted |
| 服务开始日期 | startedAt | 开通时写入 | 只读 | 试用/开通当天 `00:00:00`，时区 `Asia/Shanghai`；创建时不填 |
| 服务到期日期 | expiredAt | 开通时填写 | 日期 | 结束日 `23:59:59`；创建时不填 |
| 联系人姓名 | contactName | 否 | 输入框 | 最多 64 位 |
| 联系人手机号 | contactMobile | 否 | 输入框 | 最多 32 位 |
| 联系人邮箱 | contactEmail | 否 | 输入框 | 邮箱格式 |
| 统一社会信用代码 | creditCode | 否 | 输入框 | 最多 64 位 |
| 行业 | industry | 否 | 输入框 | 自由输入，最多 64 位 |
| 地区编码 | regionCode | 否 | 级联选择 | 省市区编码 |
| 地址 | address | 否 | 多行输入 | 最多 255 位 |
| 备注 | remark | 否 | 多行输入 | 最多 500 位 |
| 是否内置 | builtIn | 系统生成 | 标签 | `platform` 为内置租户 |
| 创建人 | createdBy | 系统生成 | 文本 | 当前操作账号 |
| 创建时间 | createdAt | 系统生成 | 文本 | 后端生成 |
| 更新人 | updatedBy | 系统生成 | 文本 | 当前操作账号 |
| 更新时间 | updatedAt | 系统生成 | 文本 | 后端生成 |
| 删除时间 | deletedAt | 系统生成 | 文本 | 逻辑删除后写入 |

不保留「联系电话」字段。

## 5.3 新增租户

入口：平台管理 / 租户管理 / 新增。

新增时填写：租户编码、名称、简称、类型、联系人、手机、邮箱、信用代码、行业、地区、地址、备注。

**不填写服务期限。**

规则：

- 默认状态为「未开通」。
- 自动插入内置角色 `TENANT_ADMIN`，名称「租户管理员」，不可改名称/编码、不可删、不可停用。
- 不自动创建管理员账号、部门、人员、菜单。
- 租户编码在「试用中」「已开通」租户之间全局唯一；已到期、已停用、已删除的编码允许被新的试用中/已开通租户使用。接受副作用：旧租户将无法再开通为试用中/已开通（会撞码）。
- 未授权任何菜单的账号，在租户可登录后允许登录并进入空首页。

标准开户顺序：

```text
创建租户 → 授权菜单/功能 → 创建账号并分配租户管理员 → 试用或开通 → 租户侧自行维护组织
```

账号可在开通前创建，但未开通时不能登录。

## 5.4 编辑租户

允许编辑：名称、简称、类型、联系人、手机、邮箱、信用代码、行业、地区、地址、备注。

不允许在编辑表单中改编码、改状态、改服务期限。

租户编码走独立操作。服务期限只通过试用/开通写入。

`platform`：可以编辑上述信息；禁止改编码、试用、开通、停用、删除、清空、授权。

## 5.5 修改租户编码

入口：租户列表或详情中的「修改编码」。`platform` 不可用。

字段：当前编码（只读）、新编码、确认文本（须等于新编码）、修改原因。

二次确认文案：

```text
租户编码是登录组织代码。修改后，该租户下所有账号必须使用新的组织代码登录。是否确认修改？
```

规则：

- 新编码不能与当前「试用中」「已开通」租户重复。
- 修改成功后旧编码不可再登录。
- 已发出的 token 等到过期自然失效（仅改编码这一种情况允许等过期）。
- 审计记录旧编码、新编码、操作人、原因。

## 5.6 租户生命周期

状态枚举：

| 状态 | 值 | 说明 | 是否可登录 | 是否可代操作 |
|---|---|---|---|---|
| 未开通 | not_opened | 已创建，尚未试用/开通 | 否 | 否 |
| 试用中 | trial | 已执行试用 | 是 | 是 |
| 已开通 | active | 已执行开通 | 是 | 是 |
| 已到期 | expired | 超过到期日 23:59:59 | 否 | 否 |
| 已停用 | disabled | 平台主动停用 | 否 | 否 |
| 已删除 | deleted | 逻辑删除 | 否 | 否 |

试用中与已开通暂时无功能差异，只是状态不同。

时区统一 `Asia/Shanghai`。

登录失败须提示具体状态，例如「当前租户未开通，请联系平台管理员」。

页面**不提供状态下来选**。只通过下列操作变更：

| 操作 | 可点状态 | 结果 |
|---|---|---|
| 试用 | 未开通、已到期、已停用 | 试用中。开始=当天 00:00:00，结束=所选结束日 23:59:59 |
| 开通 | 未开通、试用中、已到期、已停用 | 已开通。日期规则同上 |
| 停用 | 试用中、已开通 | 已停用。立即让该租户全部登录态失效 |
| 删除 | 除 `platform`、已删除外 | 已删除。立即让该租户全部登录态失效 |
| 到期自动 | 试用中、已开通，到达结束日 23:59:59 | 已到期。立即让该租户全部登录态失效 |

补充：

- 试用、开通弹窗只选结束日期；开始日期由服务器按操作当天写入，前端可用日期范围展示但开始日锁定。
- 结束日不得早于开始日；用日期范围组件避免该问题。
- 试用中再点开通 = 转正式，开始日重置为当天。
- 已到期再点试用/开通 = 续期，开始日重置为当天。
- 已开通期间不能提前续期，须到期后再开通。
- 已停用没有单独「启用」，须再点试用或开通。
- 已删除不能开通、不能恢复。
- 到期后：曾经开通或试用过（已有开始时间且开始时间已到）→ 已到期；从未开通（无日期）保持未开通。
- 停用、到期、删除须立即失效全部登录态，用户必须重新登录。改编码不必立即失效。

`platform` 状态固定为已开通，不参与到期任务，无服务期限约束。

## 5.7 租户授权

入口：租户列表 / 授权。`platform` 不走该入口；新平台菜单自动授予 `platform`。

授权内容：平台菜单目录、平台菜单、平台功能权限。

不包含：字段权限、行权限、租户内普通角色、租户自建菜单。

规则：

- 租户授权是该租户内所有角色授权的上限。
- 保存后，内置 `TENANT_ADMIN` **自动拥有**当前上限全集，并随授权变更同步。
- 租户管理员不能改 `TENANT_ADMIN` 的权限，只能在上限内给普通角色勾选。
- 租户管理员在角色管理中只能给普通角色授权租户已获得的菜单和功能。
- 取消某菜单或功能后，该租户所有角色超出上限的授权在下次请求起失效，保存授权时清理。
- 已登录用户不立即踢下线，下次请求按新权限校验。
- 字段权限由租户内角色自行配置，但字段所属菜单必须在租户授权范围内或为租户自建菜单。
- 平台管理相关菜单不得出现在授权树中。
- 平台后续新增的菜单/功能只自动授予 `platform`，其他租户必须再授权。

授权页面字段：租户名称、租户编码、菜单树、当前菜单下功能列表、最近授权时间、最近授权人。

## 5.8 租户菜单

菜单来源：

- 平台下发菜单（`source = platform`）。
- 租户自建菜单（`source = tenant`），仅自动化菜单和外部页面。

侧边栏展示：两套菜单按上级目录合并。租户自建项挂到所选父级下，与系统菜单同树渲染。

### 平台下发菜单

- 由平台超级管理员在 `platform` 的「系统管理 / 菜单管理」维护。
- 租户可将显示名称改成本租户别名，只影响本租户，不影响模板和其他租户。
- 租户不可改路径、组件、图标、权限标识、排序、状态。
- 租户不可删除、不可停用。
- 是否对租户可见由租户授权决定，再叠加角色授权。

### 租户自建菜单

- 仅本租户可见。
- 只能新建自动化菜单（低代码/报表等）和外部页面，不能新建目录，不能新建内部应用菜单。
- 创建时和创建后都可以选择、修改挂载位置（可挂在平台下发的目录下）。
- 在已获得菜单管理相关功能权限的前提下，可以修改（名称、挂载位置、绑定页面、外链地址、打开方式、启停等该类型已有字段）和删除。
- 未授予对应功能权限时，不可新增、修改、删除。
- 普通角色只要在上限内被授予这些功能，也可以操作。
- 不允许通过自建菜单突破平台上限去访问未授权的平台资源。

## 5.9 租户管理员角色

| 字段 | 值 |
|---|---|
| 角色名称 | 租户管理员 |
| 角色编码 | TENANT_ADMIN |
| 是否内置 | 是 |
| 是否可删除 | 否 |
| 是否可停用 | 否 |
| 是否可改编码 | 否 |
| 是否可改名称 | 否 |

创建租户时自动插入。清空租户数据时保留该角色，并按当前租户授权重建其权限全集。

## 5.10 账号管理租户化

账号只属于一个租户。唯一性：`tenant_id + username`。

两套列表：

| 入口 | 使用者 | 范围 |
|---|---|---|
| 系统管理 / 账号管理 | 当前租户 | 只看本租户账号。`platform` 租户在此给账号打/取消平台超级管理员标记 |
| 平台管理 / 租户账号 | 平台超级管理员 | 按租户划分，为指定租户创建账号并分配 `TENANT_ADMIN` |

规则：

- 租户管理员新增账号时所属租户固定为当前租户，不展示租户选择。
- 租户侧账号列表不可见平台超级管理员（其账号属于 `platform`）。
- 租户管理员不可创建或修改平台超级管理员。
- 登录必须传入 `tenantCode`。
- 未绑定人员账号仍允许登录。
- 代操作登录不更新该租户「最后登录时间」。

## 5.11 组织与权限租户化

以下数据均属于租户数据，必须按 `tenant_id` 隔离：

- 账号、部门、岗位、职级、人员、任职关系、上下级。
- 角色、角色账号关系、角色菜单/功能/数据/字段权限。
- 租户自建菜单及其本租户显示名。
- 低代码页面、报表、数据准备、数据清洗、流程定义与实例、业务模块数据。

全局数据：

- 租户表。
- 平台菜单模板与平台功能权限模板。
- 平台超级管理员账号标记。
- 系统字典中明确为平台级的数据。

原「职级全局维护」在租户系统下改为**按租户隔离**，每个租户各自维护职级。

## 5.12 平台超级管理员代操作

方式：在登录页填写**目标租户组织代码** + 平台超级管理员用户名密码 + 验证码。不从租户列表进入。

规则：

- 登录身份仍为平台超级管理员，上下文切到目标租户，拥有该租户全部权限（等同该租户授权上限 + 全部自建菜单能力）。
- 仅当目标租户为试用中或已开通时可进入。
- 进入后顶部展示代操作状态：目标租户名称、租户编码、平台管理员账号。
- 不展示「平台管理」。
- 退出入口即退出登录，需重新用 `platform` 组织代码登录才能回到平台。
- 若目标租户已存在同名账号，则按该租户普通账号登录，不进入代操作。

## 5.13 代操作审计

本次明确记录平台超级管理员代操作。普通操作日志可预留，不作为本期闭环。

列表筛选：租户、操作人、请求路径、操作对象类型、响应状态、操作时间。

审计字段与原先方案一致：日志ID、目标租户、操作人、请求方法/路径、操作名称、对象类型/ID、参数摘要（脱敏）、响应状态、错误信息、IP、User-Agent、Trace ID、操作时间。

## 5.14 清空租户数据

仅平台超级管理员。`platform` 不可清空。已删除租户允许清空。

清空**不删除** `sys_tenant` 本身。

清空范围：所有带 `tenant_id` 的业务表，**但保留**：

- 租户记录。
- 租户菜单/功能授权。
- 内置 `TENANT_ADMIN` 角色（并按当前授权重建权限全集）。
- 租户编码变更日志。
- 代操作审计日志。

因此账号、组织、普通角色、租户自建菜单、业务数据都会清掉。再用须重新创建账号并分配租户管理员；菜单上限仍在。

清空前展示影响范围并二次确认（输入租户编码 + 原因）。清空必须写审计。

影响范围至少包括：账号、部门、岗位、职级、人员、普通角色、角色授权、租户自建菜单、低代码页面、报表、流程定义、其他业务数据数量。

## 5.15 租户删除

逻辑删除。删除后状态为已删除，写入 `deleted_at`。不可登录、不可代操作、不可恢复。

删除不自动清空数据。清理走「清空租户数据」。

删除须二次确认（确认编码 + 原因），并立即失效该租户登录态。

`platform` 不可删除。

## 6. 迁移需求

- 所有既有账号、部门、人员、岗位、职级、角色、菜单授权、设计器资源、运行时资源和业务数据归入 `platform`。
- 新增 `tenant_id` 的历史记录统一填充 `platform` 租户 ID。
- 唯一索引租户化，例如 `username` 唯一改为 `tenant_id + username` 唯一。
- 为 `platform` 补齐内置 `TENANT_ADMIN`（若无）。
- `platform`：`tenant_code = platform`，`tenant_name = 平台管理组织`，`built_in = 1`，状态已开通。

种子账号 `platform / admin` 保持平台超级管理员标记。

## 7. 验收标准

1. 平台超级管理员可在平台管理中维护租户；非超管不可见该分组。
2. 新建租户状态为未开通，自动有 `TENANT_ADMIN`，无账号、无部门、无菜单。
3. 服务期限只能通过试用/开通写入；创建和编辑表单不填日期。
4. 页面不能把状态改成已删除；删除为独立操作。
5. 仅试用中、已开通可登录、可代操作；其他状态提示具体原因。
6. 到期日 23:59:59（上海时区）起变为已到期并立即失效登录态。
7. 停用、删除立即失效登录态；改编码等到 token 过期。
8. 平台超级管理员可在租户账号中为指定租户创建账号并分配 `TENANT_ADMIN`。
9. `TENANT_ADMIN` 自动拥有租户授权全集，租户管理员不能改该角色。
10. 登录必须传入 `tenantCode`；不同租户可存在同名账号。
11. 租户管理员只能看到和操作本租户数据，看不见平台超管账号。
12. 租户管理员只能在上限内给普通角色授权。
13. 平台下发菜单租户只能改本租户显示名；不可删、不可停用、不可改路径。
14. 租户自建仅自动化菜单和外部页面，可改挂载位置，可修改和删除（须有功能权限），按父级与系统菜单合并。
15. 新平台菜单只自动给 `platform`，其他租户须再授权。
16. 平台超级管理员用组织代码进入代操作；列表无「进入租户」；代操作时无平台管理；退出即退出登录。
17. 代操作接口调用均生成审计日志；代操作不计入租户最后登录时间。
18. 清空保留租户记录、授权和 `TENANT_ADMIN`，清掉其余带 `tenant_id` 的业务数据。
19. `platform` 受保护，列表中仅可编辑信息。
20. 历史数据迁移后归入 `platform`，原系统功能可继续使用。
