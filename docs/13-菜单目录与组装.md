# 应用功能与租户菜单组装

版本：v1.0
日期：2026-09-08  
状态：已纳入当期实施

本文记录已确认的当期方案：「应用功能」管理可用的末级功能，「租户菜单」直接完成每个租户的导航组装，不再设置独立的「菜单组装」入口。

## 1. 背景

当前菜单同时承担两件事：

- **能力登记**：页面编码、路由、组件、功能权限、表定义。
- **导航分类**：目录、上级、排序、侧栏结构。

平台「系统管理 / 菜单管理」维护的是同一棵树。租户授权只决定「给不给」，不决定「挂在哪」。因此租户侧栏会继承平台分类（例如一直挂在「系统管理」下）。

开源 admin 的使用方装了 `apps-system` 等模块后，通常也不想原样接受模块自带的一级目录，更希望把账号、人员、部门放到自己的「组织」下。

## 2. 建议拆分

| 层 | 职责 | 不管什么 |
|---|---|---|
| 能力目录 | 扁平登记可安装的页面：编码、路由、组件、功能点、来源（内部应用 / 自动化 / 外链） | 目录层级、侧栏分类 |
| 租户菜单 | 为单个租户编排目录、功能挂载、显示名称和排序 | 注册新的内部路由、组件或权限标识 |
| 租户授权 | 确定该租户可使用的菜单和功能上限 | 决定功能在侧栏中的挂载位置 |

「只新增、不管层级」指的是能力目录。树、目录、默认结构交给组装。

租户可以不依赖模块自带的**分类树**，仍必须依赖已安装模块的**页面目录**。内部应用页由代码模块贡献，组装只是挑选和分组，不能由租户发明新组件。

## 3. 租户菜单规则

1. 每个租户只有一套菜单结构，不做多套菜单模板。
2. 可新增、编辑、删除目录；删除目录时一并移除其下内容。
3. 只能选择当前租户已授权且已启用的末级应用功能。
4. 同一应用功能在同一租户菜单中最多出现一次。
5. 目录和应用功能都可修改显示名称、挂载位置和排序。
6. 应用功能的路径、组件标识、权限标识等定义字段不可在租户菜单中修改。
7. 移除应用功能只改变菜单结构，不改变租户授权上限。
8. 租户授权变更后，已保存结构中不再可用的功能自动移除。

## 4. 页面职责

- 「应用功能」使用平铺列表，只展示末级功能；新增和编辑字段保持一致，不展示类型和排序。
- 「租户菜单」展示并编辑当前租户的菜单树，提供新增目录、添加应用功能、编辑、移除和统一保存。
- 「租户授权」仍是可选应用功能的权限上限。

## 5. 明确不做

- 不新增独立的「菜单组装」页面。
- 不做多套菜单模板及模板切换。
- 不允许通过菜单组装注册新的内部路由、组件或权限标识。
- 不允许通过菜单组装突破租户授权上限。
